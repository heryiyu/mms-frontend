# 個人資訊（檢視／修改）

> 資料夾標題圖 `Tit.png`：「個人資訊修改」。

## 流程

```
首頁 → 點側邊選單／功能選單「個人資訊」（default：選單選中態）
  → 個人資訊檢視（menberinf）
  → 點右上「編輯資料」→ 資料修改（menberedit）
  → 修改欄位（menberedited）→ 點「確認」
  → 資料變更驗證 OTP（otp）→ 輸入驗證碼（otp-ing）→ 點「確認」(web) /「送出」(mob)
  → 變更完成（changed）→ 點「返回」→ 個人資訊檢視（推測）

任一步驟點「取消」(web) /「返回」(mob) → 回上一步或回檢視頁（推測，設計未標示）
```

## 設計師註記

- `點擊編輯資料進到資料修改頁面.png` ＝「點擊編輯資料進到資料修改頁面」：指個人資訊檢視頁（menberinf）右上的「編輯資料」連結，點擊後進入資料修改（menberedit）。

## 需要的 API（推測，後端未定）

- `GET /me`：取得會員資料（姓名、暱稱、性別、身分證字號、信箱、手機、教會、牧區、小組、EKK、靈程）。身分證字號、手機是否由後端遮罩回傳需確認。
- `POST /me/profile-change/otp`：送出修改內容（姓名、暱稱、信箱、手機）並寄送 OTP，回傳有效秒數（畫面顯示倒數）。
- `POST /me/profile-change/verify`：送出 OTP 驗證碼，驗證通過後正式更新資料。
  - 另一種做法：`PATCH /me` 帶 `{ changes, otp }` 一次送出；需與後端討論。
- `POST /me/profile-change/otp/resend`：重新寄送 OTP（設計未畫，但倒數歸零後應需要）。

## 待確認

- OTP 寄到哪裡？手機簡訊還是信箱？若使用者正在修改手機／信箱，是寄到舊的還是新的？
- OTP 長度（範例為 5 個 X）與有效時間（顯示 4：50，總長是 5 分鐘嗎？）。
- 倒數歸零後的狀態、「重新發送」按鈕、驗證碼錯誤的錯誤訊息，設計都沒畫。
- web 檢視頁（menberinf）底部出現「取消／確認(停用)」，唯讀頁有確認按鈕不合理，是否應改為與 mob 一致只有「返回」或不顯示？
- web 編輯頁仍顯示「編輯資料」連結，點了要做什麼？是否應隱藏（如 mob）？
- web 編輯頁「確認」在未修改任何欄位時即可點，是否應改為有變更才可點？
- mob menberedited 底部只剩「返回」、沒有「確認」，與 menberedit 不一致；推測為設計稿遺漏，應為「返回＋確認」。
- 「取消」/「返回」行為：回檢視頁並捨棄修改？是否需要「確定放棄修改？」確認彈窗？
- 欄位格式驗證與錯誤訊息文案（信箱、手機、姓名長度、暱稱長度）未定義；編輯頁信箱／手機範例值為「XXXXXXX」，無法判斷是否帶入完整值或遮罩值。
- 檢視頁欄位：EKK、靈程的意義與值來源（範例 Hooo、XN）；未看到「生日」、「地址」等欄位，確認會員資料是否就這 11 項。
- 麵包屑全部都是「首頁」，個人資訊頁是否應顯示「首頁 / 個人資訊」？
- 變更完成後「返回」去哪裡：個人資訊檢視還是首頁？首頁橫幅暱稱需同步更新。

## 用到的共用元件

- **側邊選單（web）／mob Top Bar＋功能選單抽屜**：見 `../member-home/README.md`。
- **頂部麵包屑列（web）**。
- **頁面標題列**：左標題＋右側文字連結（「編輯資料」＋圖示）。
- **描述列表卡片（Descriptions）**：左 label／右值，列間分隔線（適合 Ant Design `Descriptions` 或自訂 List）。
- **表單卡片（label 左、輸入框右）**：列間分隔線；與修改密碼共用。
- **底部操作列（Bottom Action Bar）**：固定在內容區底部、上方分隔線；web 置中兩顆膠囊「取消（次要）＋確認（主要）」；mob 兩顆等寬「返回＋確認／送出」或單一滿版「返回」；主要按鈕有停用態（gray4 底）。
- **OTP 輸入＋有效時間倒數框**：輸入框與灰底倒數框並排。
- **結果頁（Result）**：主色勾勾圖示＋「變更完成！」＋「返回」文字連結；與修改密碼共用。
